## 2. 캐릭터 — 우선순위 순

### ① 걷기 2장 ★가장 급함
지금 어느 방향으로 걸어도 정면 서기 한 장만 나온다. 이 두 장이 체감을 가장 크게 바꾼다.

```
(공통 규칙 + 팔레트)
달라지는 건 다리 자세뿐이야. 몸통·머리·꼬리·팔은 첨부 그림과 똑같이.

1장: 왼쪽 뒷발이 앞으로 나가고 오른쪽 뒷발이 뒤로 간, 걷는 중간 자세.
```
두 번째 장은 같은 프롬프트에서 좌우만 반대로. **한 번에 한 장씩** 요청할 것.

### ② 옆모습 서기 (오른쪽 봄)
```
(공통 규칙 + 팔레트)
오른쪽을 바라보는 옆모습. 얼굴이 옆으로 보이고 눈은 하나만 보인다.
주둥이와 코가 오른쪽을 향한다. 귀 두 개가 옆에서 보이는 형태.
꼬리는 몸 뒤쪽(왼쪽)으로 나와 위로 휜다.
```
**왼쪽 방향은 만들 필요 없다** — 클라이언트가 좌우 반전해서 쓴다.

### ③ 대각선 앞 (오른쪽 앞을 봄)
```
(공통 규칙 + 팔레트)
오른쪽 앞을 비스듬히 바라보는 자세. 정면과 옆모습의 중간.
양쪽 눈이 보이되 오른쪽 눈이 더 크고 주둥이가 살짝 오른쪽으로 치우친다.
```

### ④ 뒷모습
```
(공통 규칙 + 팔레트)
뒷모습. 얼굴은 전혀 보이지 않고 뒤통수와 귀 두 개, 등, 꼬리만 보인다.
셔츠의 등판이 보인다. 꼬리가 등 뒤에서 위로 휜다.
```

### ⑤ 대각선 뒤 (오른쪽 뒤를 봄)
```
(공통 규칙 + 팔레트)
오른쪽 뒤를 비스듬히 바라보는 자세. 뒷모습과 옆모습의 중간.
얼굴은 거의 안 보이고 뺨과 귀 윤곽만 살짝 보인다.
```

### ⑥ 앉기
```
(공통 규칙 + 팔레트)
의자에 앉은 자세. 엉덩이가 바닥에 닿고 뒷다리가 앞으로 접혀 있다.
꼬리는 옆으로 늘어뜨린다. 상체와 얼굴은 정면.
```

### ⑦ 감정표현 (여유 있을 때)
- **춤**: 두 팔을 위로 올리고 몸이 한쪽으로 기울어진 자세
- **손인사**: 오른쪽 앞발을 머리 높이로 들어 올린 자세
- **잠**: 옆으로 누워 눈을 감고 몸을 동그랗게 만 자세

## 2-1. 캣닢 화분 · 캣닢 잎 (디자인 확정됨 — 시트를 컷으로 다시 받기)

사용자가 만든 **디자인 시트**가 있다(빈 화분 → 1~5 → 6~15 → 16~29 → 30줄기, 각도 4종, 인벤토리 아이콘, 코인 교환 UI).
디자인은 이걸로 확정. 다만 시트는 **한 장에 여러 컷 + 베이지 배경 + 라벨**이라 그대로는 못 쓴다 → **컷을 한 장씩 다시 받는다.**

### 받을 파일 (이 이름 그대로 `art/ref/` 에)

| 파일명 | 시트의 어느 그림 | 아틀라스 키 |
|---|---|---|
| `flower_pot_0_seed.png` | 비어있는 화분 (흙만) | `flower_pot_0_seed_0` |
| `flower_pot_0_sprout.png` | 1~5줄기 | `flower_pot_0_sprout_0` |
| `flower_pot_0_bud.png` | 6~15줄기 | `flower_pot_0_bud_0` |
| `flower_pot_0_bloom.png` | 30줄기 (완성, 반짝임 포함) | `flower_pot_0_bloom_0` |
| `flower_cut_0_default.png` | 캣닢 한 줄기 | `flower_cut_0_default_0` |

> 키 형식은 `{furniId}_{방향}_{상태}_0`. **방향은 0 하나뿐** — `flower_pot`/`flower_cut` 은 `rotations: [0]` 이라 회전하지 않는다.
> 그래서 시트의 **측면·후면·사선 3종은 지금 쓸 데가 없다.** 회전 가구로 바꾸기 전에는 그리지 말 것.
> 16~29줄기 컷을 살리려면 `data/furni/flower_pot.json` 의 상태를 5개로 늘려야 한다(JSON 한 장이면 된다).

### 프롬프트 (한 번에 한 장씩, 시트를 첨부하고)

```
첨부한 캣닢 화분 디자인과 완전히 같은 그림을 그려줘.
화분 색, 고양이 얼굴 무늬, 잎 모양과 색, 선 굵기, 화풍 모두 첨부와 동일하게.

[ 여기에 한 줄만: "비어있는 화분(흙만 보임)" / "잎이 1~5장 올라온 상태" /
  "잎이 6~15장으로 제법 무성한 상태" / "잎이 30장으로 꽉 차고 반짝임이 있는 완성 상태" ]

화분 하나만 크게, 화면 가운데에. 정면에서 본 모습.
배경은 완전 투명. 바닥 그림자나 받침은 그리지 말 것.
여러 단계를 한 장에 모으지 말 것. 라벨·설명 글자를 넣지 말 것.
색은 16개 이하. 도트 아트, 안티앨리어싱 없음.
```

캣닢 잎(가방 아이템)은 마지막 줄만 바꾼다: `잎이 달린 캣닢 줄기 하나만. 화분 없이.`

### 크기 감각
타일이 64×32, 고양이가 53×69 다. **화분은 폭 40 안팎**(고양이 허리 높이), **캣닢 잎은 24 안팎**이면 어울린다.
정확한 크기는 맞추지 않아도 된다 — 원본 격자를 복원해서 쓰므로 **줄이지 않고 그대로** 주는 게 중요하다.

## 4. 만든 그림을 게임에 넣는 절차 (참고)

1. `art/ref/` 에 넣고 파일명 알려 주기
2. 격자 복원 → `client-godot/art/atlas.png` 갱신 (한 칸 = 한 픽셀, 최빈색, 줄이지 않음)
3. `atlas.json` 에 키 추가 — `avatar/{파츠}/{모델}_{방향}_{동작}_{프레임}`
   - 방향 0=뒤 1=대각뒤 2=옆 3=대각앞 4=정면 (5~7은 좌우 반전으로 자동)
   - 동작 `stand` `walk` `sit` `dance` `wave` `sleep`
4. **`tools/import-assets.ps1` 실행** — Godot 은 이걸 안 돌리면 새 PNG 를 못 읽는다
5. 실행해서 확인

## 5. AI 로 도트를 만들 때 알아둘 것

- 생성 AI 는 **"픽셀 아트 풍"** 을 그리지 진짜 도트를 찍지 않는다. 격자가 균일하지 않다(이번 고양이는 한 칸이 8~17픽셀로 들쭉날쭉했다).
- 그래서 **임의 크기로 줄이면 반드시 깨진다.** 첫 시도에서 53×69를 40×48로 줄였다가 귀 두께가 좌우로 달라졌다. 원본 격자를 복원해 쓰는 게 정답.
- 색은 수백 개로 나온다. 거의 같은 크림색이 수십 가지다. 16색으로 줄이면 눈에 안 띄게 정리된다.
- **한 번에 한 장씩.** 시트로 달라고 하면 칸 간격과 색이 어긋난다.
- 원본 IP 의 실제 에셋은 참고하지 않는다(`LEGAL.md`). 분위기만 보고 우리 색·우리 비율로 다시 만든다.
